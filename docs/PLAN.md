# moni_token — 구성안

- 상태: **초안** (2026-10-06, 지휘부 작성). 구현 착수는 지휘부 지시 후.
- 한 줄 요약: **Claude Code 사용량이 갑자기 치솟으면 알리고, "왜 치솟았나"(어느 세션·어떤 작업·무엇 때문)를 로컬 로그로 분석해 사건으로 남기며, 사용량 추이와 사건 목록을 웹페이지로 보여 주는 도구.**

## 1. 왜 만드나

**계기(2026-10-06):** 사용량 한도가 초기화된 뒤 50분 만에 5%가 빠졌는데, 체감 작업은 가벼웠다. 원인은 아침부터 이어진 긴 대화(컨텍스트)에서 도구 호출이 34회 넘게 일어나, 호출마다 하루치 대화를 다시 보낸 것으로 추정됐다. 이걸 사람이 대화로 캐물어야만 알 수 있었다. 같은 날 밤에 작곡(RunPod)·Mnemento 작업을 여러 세션으로 돌릴 예정이라, 예측 못 한 급증을 바로 알고 원인을 남길 장치가 필요해졌다.

**선행 도구(2026-10-06 검색 1회, 착수 전 재확인):**

| 도구 | 하는 일 | 빈 곳 |
|---|---|---|
| ccusage | 로컬 로그 파싱 → 일·세션·5시간 구간 집계, `blocks --live` | 원인 분석·사건 기록 없음 |
| claude-monitor (Claude Code Usage Monitor) | 터미널 실시간 대시보드, 사용 속도·한도 도달 예측, 80/90/95% 알림 | 왜 빨라졌는지 모름 |
| ccflare | localhost 웹 UI(시간대별 토큰·세션별 비용·속도 추이) | 사건·원인 없음 |
| claude-usage-monitor | 상태줄·ETA·알림·한도 전 체크포인트 | 원인 없음 |

→ **moni_token이 채우는 곳: 급증 사건의 원인 분석과 기록.** 집계·한도 추정 로직은 바퀴를 새로 만들지 말고 기존 도구의 방식을 참고(라이선스 확인 후 가져다 쓰기 가능하면 그쪽).

## 2. 설계 원칙

0. **★LLM 0회 (최우선, 사용자 지시 2026-10-06)** — 토큰을 아끼려는 도구가 토큰을 쓰면 안 된다. 원인 분석은 §4.3의 **결정론적 규칙**(임계값·비율·순위)으로 판정하고, 사건 설명·권고 문장은 **템플릿**으로 만든다. 실행 중 Anthropic API·`claude -p`·LLM 경유 MCP 호출 0회. 이 원칙은 테스트로 강제한다(네트워크 차단 상태에서 전 기능 동작 + 코드에 LLM 클라이언트 import 없음 검사).
1. **원문 미저장** — 숫자와 메타데이터만(CLAUDE.md 절대 규칙 1).
2. **로컬 전용** — 전송 없음, 웹은 로컬.
3. **급증 판정은 설명 가능해야 한다** — "평소 대비 N배" 같은 기준과 근거 수치를 사건에 함께 남긴다.
4. **원인은 추정임을 표시** — 로그로 확인된 사실(호출 수·컨텍스트 크기)과 해석("긴 대화 × 많은 호출")을 구분해 기록.
5. **가볍게 상주** — 로그를 처음부터 다시 읽지 않고 파일별 오프셋으로 증분 수집. 무관한 작업에 부담 0에 가깝게.

## 3. 데이터

- 원천: `~/.claude/projects/<프로젝트>/<세션>.jsonl` (서브에이전트·사이드체인 로그 포함 여부는 M0에서 실측).
- 호출(assistant 메시지) 단위로 뽑을 것: 시각, 세션 id, 프로젝트 폴더, 모델, `usage`(input / output / cache_creation / cache_read 토큰), 그 응답이 부른 도구 이름들, 직전 도구 결과의 크기(이미지 여부·바이트 수), 사람 입력인지 도구 결과에 대한 후속 호출인지.
- 저장: 로컬 SQLite(`~/.moni_token/usage.db`) — 호출 표, 5분 버킷 집계, 사건 표.
- **범위 밖(한계로 명시):** claude.ai 웹 대화, 클라우드 Claude Code 세션, 다른 PC. 이들도 같은 계정 한도를 쓰지만 로컬 로그에 없다. RC(Remote Control) 모드는 이 PC 세션이라 포함.

## 4. 기능

### 4.1 사용량 추정
- 토큰 종류·모델별 가중치(가격표 기반 비용 환산)를 "사용량 단위"로 쓴다. 한도 대비 %는 계정 값이라 로컬에선 **추정**.
- **보정 기록:** 사용자가 화면에서 본 % (예: "10/06 15:06~15:56에 5%")를 입력하면 그 구간의 사용량 단위와 짝지어 저장 → 쌓일수록 "1% ≈ N 단위" 추정이 정확해진다.
- 5시간 구간(한도 초기화 기준) 추적과 현재 속도로의 도달 예상 시각.

### 4.2 급증 탐지
- 최근 5분·15분 속도를 직전 기준선(예: 지난 1시간 중앙값)과 비교해 N배 이상이면 사건. 절대 하한(아주 작은 값의 배수 급증은 무시)과 재알림 간격 포함. 기준값은 설정 파일.
- 알림: Windows 토스트(moni_pod에서 검증된 방식: 훅/프로세스 안에서 동기 실행해야 실제로 뜸).

### 4.3 원인 분석 (핵심)
사건 구간에서 사용량을 세션별로 나누고, 상위 세션마다 아래를 계산해 원인 유형을 붙인다.

| 원인 유형 | 판정 근거(예) |
|---|---|
| 긴 대화 × 잦은 호출 | 호출당 cache_read가 큼 + 구간 내 호출 수 많음 (10/06 사례) |
| 큰 입력 | 이미지·대용량 파일·첨부 원문을 읽은 직후 컨텍스트 급증 |
| 서브에이전트·병렬 세션 | 같은 시각 여러 세션·사이드체인 동시 활동, headless(`claude -p`) 세션 |
| 웹 조사 다수 | WebSearch·WebFetch 호출 집중 |
| 출력 폭주 | output 토큰 비중 급증(긴 생성·반복) |
| 캐시 미스 | cache_creation 급증(캐시 만료 후 재생성, 5분/1시간 TTL) |
| 공백 후 재개(캐시 만료) | 같은 세션에서 TTL보다 긴 공백 뒤 첫 호출이 큰 컨텍스트 전체를 다시 캐시에 씀(10/06 15:56 사례: 3시간 공백 → 1h 캐시 쓰기 458k). 권고: "1시간 넘게 쉰 큰 세션은 이어쓰지 말고 새 세션" |

사건 기록: 시각, 구간, 사용량, 기준 대비 배수, 상위 세션(프로젝트·세션 id), 원인 유형과 근거 수치, 권고(예: "새 세션 시작", "/compact", "원문은 파일로").

### 4.4 웹페이지 (로컬)
- 사용량 추이 그래프(시간축, 프로젝트·세션별 누적 영역), 5시간 구간 경계, 사건 표시.
- 사건 목록(시각·배수·원인 유형·상위 세션·근거), 사건을 누르면 그 구간의 호출 타임라인.
- 정적 HTML 생성 또는 작은 localhost 서버 — M0에서 결정.

### 4.5 실행 형태
- 상주 수집기(백그라운드, 1~2분 주기 증분). 자동 시작 방식(작업 스케줄러 / SessionStart 훅)은 M0에서 결정.
- (선택) Claude Code 상태줄에 현재 속도·5시간 구간 사용량.
