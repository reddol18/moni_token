# ADR-0006: 다국어 — 메시지 카탈로그와 사건의 템플릿 키 저장

- 상태: 채택 (issue #12, 2026-11-13)

## 맥락

화면·알림·상태줄·CLI 문장이 전부 한국어로 코드에 박혀 있었다. 영어 사용자도 쓸 수 있어야 하고, 실행 중 LLM·기계번역은
금지다(CLAUDE.md 규칙 2). 사건(events 테이블)은 완성된 한국어 문장을 저장해 왔다.

## 결정

1. **카탈로그**: `src/moni_token/locales/<lang>.json`, 키에 `{자리표시자}`. Python 쪽은 `str.format` 서식(`{share:.0%}`),
   페이지 쪽 키(`p.`)는 단순 `{name}`만 쓰고 페이지가 `T(key, vars)`로 채운다. 빠진 키는 영어, 그다음 키 자체로 대체.
2. **언어 선택 순서**: `--lang`/`?lang=` → `config.toml`의 `lang` → OS 로캘 → 영어. Windows는 `_locale._getdefaultlocale()`
   (ctypes·locale 모듈 없이, 상태줄 비용 때문).
3. **페이지**: 서버가 선택된 카탈로그의 `p.` 문자열을 `window.I18N`으로 심고, HTML의 고정 문구는 `[[key]]` 표식을 서버에서
   치환한다. 날짜·숫자는 `Intl`(24시간제, `hourCycle: 'h23'`). 셸에 언어 전환 버튼(ko⇄en), 선택은 `localStorage`(try/catch)
   + `?lang=`로 적용, 탭·"그때 지도" 링크·`/api/state`에 `lang`을 실어 보낸다. 정적 report.html은 쓸 때 언어가 정해지므로
   전환 버튼을 두지 않는다.
4. **사건**: 스키마는 바꾸지 않는다(`SCHEMA_VERSION` 유지 — 올리면 사건·예측 기록이 사라진다). `causes_json`의 각 원인에
   `params`(사실·해석 문장의 값), `alt_key`·`alt_params`(대안 문장)를 함께 저장한다. 표시할 때마다 현재 언어로 다시 만든다.
   headline 열은 대체값이고, 표시는 첫 원인에서 다시 만든다.
5. **이전 행**: 키가 없는 한국어 문장은 한국어 템플릿과 정규식으로 맞춰 숫자를 되찾고(`i18n.unformat`) 다시 렌더한다.
   맞지 않으면 저장된 문장을 그대로 보인다. 실제 DB 1,314개 원인 전부 복원됐고, 한국어로 다시 만든 결과는 저장된 문장과
   글자 하나 다르지 않았다.
6. **상태줄**: `check`가 `spike_now.json`에 `kind`·`rise_pp`·`code`를 함께 쓰고, 상태줄은 DB 없이 그 값으로 문장을 만든다.

## 대안

- 페이지에 두 언어를 모두 심고 JS로 전환: 정적 파일에서도 전환되지만 페이지가 커지고 서버 문장(원인·요약)을 두 벌 만들어야 함.
- events에 열 추가(`ALTER TABLE`): JSON 안에 넣으면 되므로 불필요.
- gettext/.po: 의존성·빌드 단계가 늘어남. JSON 두 파일이면 충분.

## 결과

- `tests/test_i18n.py`: 키·자리표시자 일치, 소스 안 한글 금지(카탈로그 밖), 영어 페이지에 한글 없음, 언어 선택 순서,
  이전 행 복원, 알림·상태줄·CLI 영어.
- 한국어 화면의 날짜 표기가 `11-13 09:19`에서 `Intl` 한국어 형식 `11. 13. 09:19`로 바뀌었다.
- 영어로만 출력하던 CLI 명령(`collect`, `daily`, `status`, `calibrate`, `forecast` 등)은 카탈로그로 옮기지 않았다.
  두 언어에서 같은 출력이고, 한국어 사용자의 동작을 바꾸지 않기 위해서다.
