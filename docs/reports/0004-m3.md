- `analysis.py`: 구간 → 세션별 분해(상위 세션부터 누적 80%까지) → 규칙으로 원인 판정. 규칙 파라미터는 `CauseParams`에 모았다.
  - 원인 유형:
    - **공백 후 재개**: TTL(1h 또는 5m)보다 긴 공백 뒤 캐시 쓰기 ≥100k
    - **긴 대화 × 잦은 호출**: 컨텍스트 중앙값 ≥200k, ≥20회, 캐시 읽기 비중 ≥40%
    - **캐시 미스**: 공백 없이 일어난 캐시 쓰기 비중 ≥40%
    - **큰 입력**: 직전 결과·첨부 ≥100KB 또는 이미지 뒤의 캐시 쓰기
    - **병렬**: ≥3회 호출한 세션이 3개 이상, 또는 사이드체인·headless 호출이 있음
    - **웹 조사**: ≥10회
    - **출력 폭주**: output 비중 ≥40%
  - 각 원인은 **사실**(로그 숫자) / **해석**(템플릿, 항상 "(추정)") / **권고**로 나눠 남긴다. 귀속 금액 순으로 정렬한다.
  - 모든 분석에 "output 토큰은 과소일 수 있음"을 붙인다.
- `events.py` + `events` 표: 급증(속도·캐시 쓰기)과 사용자 지정 구간(`manual`)을 근거와 함께 저장한다. 같은 사건을 다시 기록해도 중복되지 않는다.
- `check`는 사건을 저장하고, 토스트에는 1순위 원인의 사실과 권고를 넣는다.
- CLI: `analyze --from --to [--save] [--json]`, `events`, `backfill-events`.
- 사용자 확정 기준값은 `~/.moni_token/config.toml`에 넣었다: floor $12.14 고정, ×3, 200k, 30분.
